# API и веб-виджет

После запуска интерактивная OpenAPI-документация доступна по адресу `http://localhost:8000/docs`.

## POST /message

Создаёт или продолжает диалог.

```json
{
  "anonymous_id": "browser-user-1",
  "channel": "website",
  "session_id": null,
  "content": "Хочу купить Toyota Camry до 3 миллионов",
  "page_title": "Toyota Camry в наличии"
}
```

| Поле | Обязательное | Описание |
|---|---:|---|
| `anonymous_id` | да | Стабильный ID, созданный клиентом; от 3 до 128 символов |
| `channel` | нет | `website`, `telegram` или `avito`; по умолчанию `website` |
| `session_id` | нет | UUID существующей активной сессии |
| `content` | да | Сообщение пользователя; от 1 до 4000 символов |
| `page_title` | нет | Нормализованный заголовок страницы; не более 200 символов |

API-схема принимает значения каналов `telegram` и `avito`. В репозитории
реализованы виджет для сайта, прямой вызов API и интеграция с Telegram через long polling;
готовой интеграции с Avito пока нет.

Пример ответа:

```json
{
  "user_id": "0c336b9b-6a7e-4494-8af1-e6302b87956f",
  "session_id": "c75f9b38-b169-4901-a3e1-9335d4d7ff6a",
  "user_message_id": "57c7b362-4b4d-4e5f-8a9b-1c2d3e4f5a6b",
  "assistant_message_id": "bb9ffb5f-d98c-4cc2-bf7e-c6e5dfde4b63",
  "answer": "Какой способ покупки вы рассматриваете?",
  "state": "QUALIFICATION",
  "intent": "lead_request",
  "next_step": "QUALIFICATION",
  "missing_fields": ["purchase_type", "contact"],
  "lead_id": "9f1c0c2a-3b4d-4e5f-8a9b-1c2d3e4f5a6b"
}
```

Диалоговый `answer` формирует LLM, в том числе для сообщения только с контактом.
При недоступности провайдера или невалидном ответе модели сохраняется технический
ответ «Извините, не удалось обработать запрос. Попробуйте ещё раз.».
Если LLM повторно нарушает контракт коррекции намерения, API возвращает `502`
с `detail: "Agent response unavailable"`; изменения этого запроса не сохраняются.

## Сессии и сообщения

```text
GET /sessions/{session_id}
GET /sessions/{session_id}/messages
```

Первый метод API возвращает состояние и владельца сессии. Второй возвращает
сохранённую историю сообщений в порядке создания.

## Лиды

```text
GET  /leads
GET  /leads?status=ready
GET  /leads/{lead_id}
POST /leads/{lead_id}/deliver
```

`GET /leads` возвращает сокращённые элементы списка. `GET /leads/{lead_id}`
дополнительно содержит квалификацию, контакт, краткое описание, статус доставки
и последнюю ошибку.

`POST /leads/{lead_id}/deliver` синхронно повторяет доставку без Redis. Метод
возвращает `404` для неизвестного лида и `409` для лида в недопустимом статусе,
например `draft`.

## База знаний

```text
GET  /knowledge/documents
POST /knowledge/documents
PUT  /knowledge/documents
POST /knowledge/reindex
```

Документы загружаются вручную JSON-массивом:

```json
[
  {
    "title": "Toyota Camry",
    "source": "manual",
    "content": "Toyota Camry доступна в комплектациях ..."
  }
]
```

`PUT /knowledge/documents` атомарно заменяет весь корпус; пустой массив
возвращает `422`. Документы делятся на чанки и индексируются вместе с заголовком.
По текущей реплике выполняется прямой векторный поиск по всему корпусу.
В контекст попадают до `RAG_TOP_K` фрагментов выше `RAG_MIN_SCORE` из любых
документов. Переписывания запроса и привязки к прошлому источнику нет.
После смены модели или правил индексирования вызовите `POST /knowledge/reindex`.

База знаний считается публичной справочной информацией компании. Её телефоны,
email и Telegram передаются LLM как `[KB_CONTACT_N]`; backend восстанавливает
только контакты текущих найденных фрагментов в ответе пользователю. Они не
становятся контактами клиента. Личные контакты в этот корпус загружать не следует.

## Демонстрационная страница

Страница раздаётся через FastAPI, без frontend-сборки и установки npm-пакетов:

Демонстрационная страница:

```text
http://localhost:8000/static/widget-demo.html
```

Открывайте страницу с того же API, с которым хотите вести диалог: запросы идут
на `POST /message` текущего сервера. Для запущенного Compose-контейнера используйте
порт `8000`. Порт `8017` в браузерных тестах относится к отдельному API с заглушкой
и временной БД; он не подключает страницу к модели из рабочего контейнера.

HTML, стили, логика и список тематик находятся в `static/widget-demo.html`,
`static/demo.css`, `static/demo.js` и `static/demo-config.js`. Старый встраиваемый
`widget.js` и демонстрация карточки Toyota удалены.

Работает только «Автосалон»: выбор отправляет обычное сообщение в `POST /message`.
Остальные карточки отключены. Сервер не принимает отдельный параметр тематики
и не возвращает быстрые ответы: интерфейс предлагает их только для нескольких
явных вопросов об автомобиле и способе покупки.

История, `anonymous_id` и `session_id` сохраняются в отдельном ключе
`innova_demo_v1` в `localStorage`. «Очистить чат» отменяет ожидание ответа,
создаёт новый `anonymous_id`, удаляет ссылку на прежнюю сессию и показывает
приветствие. Следующее сообщение создаёт отдельного анонимного пользователя
и сессию. Это изолирует новый контекст: удаление одного `session_id` вернуло бы
активную сессию того же пользователя. Записи прежнего диалога остаются в БД;
API удаления/сброса сессии отсутствует.

После сетевой ошибки доступен ручной повтор. В API нет ключа идемпотентности:
если сервер обработал запрос, но ответ потерялся, повтор может создать второе
сообщение в БД. Отмена ожидания в браузере также не отменяет уже начатую
обработку на сервере; её поздний ответ не попадёт в очищенный чат.

В футтере справа находится ссылка «Автор проекта» на
`https://github.com/GeorgiiSadunyan`. Она задана в HTML и доступна без JavaScript.
Medeo Sans 1.0.0 из npm-пакета `medeo-font` хранится локально вместе с лицензией
SIL OFL в `static/fonts/`. Все 11 изображений из `Pictures/INNOVA` переведены в
WebP с сохранением размеров и прозрачности. Аватар из
`static/images/assistant.webp` показан в круглой рамке, без увеличения изображения.

Два ряда бизнесов прокручиваются непрерывно в одном направлении через Embla
Carousel + Auto Scroll 8.6.0. UMD-файлы и MIT-лицензия находятся в
`static/vendor/embla-carousel/`; CDN не требуется. Embla перемещает исходные
карточки без копий в DOM. Доступны перетаскивание мышью, свайпы, стрелки,
Home и End. При наведении движение продолжается; при фокусе внутри карусели
и в скрытой вкладке автоматическая прокрутка приостанавливается. После жеста
прокрутка возобновляется, если фокус вне карусели. В режиме
`prefers-reduced-motion` автоматическое движение отключено.

Настройка CORS и запуск описаны в [инструкции по разработке](DEVELOPMENT.md).
