# CI/CD

Pipeline CI/CD определён в `.github/workflows/pipeline.yml` и работает только с
веткой `main`:

- запрос на слияние в `main`: форматирование, Ruff, mypy, миграции, pytest и
  тестовая сборка образа Docker;
- отправка изменений в `main`: те же проверки, публикация образа с полным
  Git SHA в GHCR и автоматическое развёртывание на VPS;
- остальные ветки не запускают Pipeline.

Метка `latest` не используется. API, фоновый обработчик, Telegram и Alembic
получают один неизменяемый образ вида:

```text
ghcr.io/kng-labs/innova-ai:<full-git-sha>
```

## Состав рабочей среды

Рабочая среда разворачивается через `docker-compose.prod.yml`:

- PostgreSQL 17 с pgvector и Redis хранят данные в именованных томах;
- одноразовый сервис `migrate` применяет миграции Alembic;
- API, фоновый обработчик и бот Telegram запускаются из одного образа приложения;
- PostgreSQL и Redis не публикуют порты хоста;
- API доступен только на `127.0.0.1:8000`.

Домен и обратный прокси-сервер не требуются для текущего сценария Telegram long polling.
Swagger, административные методы API и загрузка RAG доступны через
SSH-туннель.

## Развёртывание

При отправке изменений процесс GitHub Actions передаёт на VPS Compose-файл и
скрипты развёртывания. Далее система:

1. блокирует параллельный запуск;
2. запускает и проверяет PostgreSQL и Redis;
3. создаёт сжатый `pg_dump`;
4. применяет `alembic upgrade head`;
5. обновляет API, фоновый обработчик и Telegram;
6. проверяет состояние сервисов и сохраняет текущую и предыдущую версии.

`GET /health` возвращает `200`, только если API может выполнить запрос к
PostgreSQL. Redis и внешние поставщики не входят в проверку состояния.

При неуспешной проверке состояния выполняется автоматический откат на предыдущий
образ. Откат не выполняет `alembic downgrade`, поэтому миграции должны оставаться
совместимыми с предыдущей версией приложения.

## Обязательная настройка

Окружение GitHub `production` хранит параметры SSH для VPS:

```text
VPS_HOST
VPS_PORT
VPS_USER
VPS_SSH_PRIVATE_KEY
VPS_SSH_KNOWN_HOSTS
```

Секреты хранятся только в защищённом файле окружения на VPS. Рабочая среда
использует внутренние имена сервисов Compose `db`, `redis` и `api`, режимы
`ag2`/`openrouter`/`amocrm`, а также учётные данные OpenRouter, AmoCRM и Telegram.

Подготовка VPS, команды проверки и ручного отката — в [инструкции по развёртыванию](VPS_DEPLOY.md).
