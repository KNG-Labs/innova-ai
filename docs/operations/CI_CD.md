# CI/CD

Единственный workflow — `.github/workflows/pipeline.yml`.

- Pull request в `main`: проверка uv.lock, форматирование, Ruff, mypy,
  миграции, pytest и DOM-тесты страницы чата.
- Push в `main`: те же проверки, затем задача `deploy-vercel` с `needs: checks`.
- Другие ветки не публикуются. PR не получает секретов облака.

Тесты используют временную PostgreSQL `innova_ai_test` с pgvector и заглушки
LLM/embeddings. Внешние AI API в CI не вызываются.

## Выпуск на Vercel

Задача выпуска работает в GitHub Environment `production`, только для `main`.
Версии Vercel CLI, uv и GitHub Actions закреплены. Checkout задачи выпуска
не сохраняет GitHub credentials. Выпуски одной ветки не прерывают друг друга.

1. Получить production-настройки через `vercel pull`.
2. Собрать функцию через `vercel build --prod`. Python builder устанавливает
   только runtime-зависимости из uv.lock (`--no-dev`). В CLI 65.16.0 нативная
   команда build зависает; workflow запускает поставляемый с этой версией
   JS runner. Остальные команды используют обычный CLI.
3. Проверить, что `DEMO_DATABASE_URL` указывает на выделенную `innova`
   в Neon, использует asyncpg, прямой адрес и `ssl=verify-full`.
4. Применить миграции с явно заданным `DATABASE_URL`.
5. Если база знаний пуста, загрузить `docs/RAG/Agent_memory.txt` через
   существующий `KnowledgeIngestionService`. Заполненная база не меняется;
   embeddings повторно не оплачиваются.
6. Загрузить собранный артефакт через
   `vercel deploy --prebuilt --prod --skip-domain`.
7. Проверить `/health`, перенаправление на чат, статические файлы и HTTP 404
   для административных маршрутов. `vercel curl` обслуживает защищённый адрес
   сборки; проверка не отправляет сообщений и не создаёт диалогов.
8. Переключить адреса только после успешных проверок и дождаться завершения.
   В CLI 65.16.0 `vercel promote` получает HTTP 404 при поиске пользователя
   с CI-токеном. `scripts.promote_vercel` выполняет ту же операцию через
   официальный API с явными ID проекта и команды. Перед переключением он
   проверяет принадлежность сборки, production-окружение и состояние READY;
   ошибка назначения адресов или тайм-аут завершают выпуск с ошибкой.

Независимые Git-деплои Vercel выключены через `git.deploymentEnabled=false`.
Точка выпуска — GitHub Actions, поэтому непрошедший CI код не публикуется.
Новые PR-превью в этой версии не создаются.

## Ошибки и откат

Провал CI блокирует задачу выпуска. При ошибке сборки, миграции, начальной загрузки
знаний или проверки доступности публичный адрес остаётся на предыдущей версии.
Миграции выполняются до переключения адреса, поэтому должны быть совместимы
с предыдущей версией приложения.

Откат кода: `vercel rollback <previous-deployment-url>`. Он не откатывает схему
БД и не удаляет сохранённые диалоги. Для возобновления выпуска используется
обычный успешный pipeline с переключением проверенной сборки.

Настройки облака, секретов и бюджета: [Vercel deploy](VERCEL_DEPLOY.md).
Сборка Docker, GHCR и SSH-деплой удалены из workflow; локальная конфигурация Docker
сохранена. VPS больше не обновляется автоматически, но продолжает существовать.
